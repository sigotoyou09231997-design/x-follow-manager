# Yay自動投稿（poster/yay）

yay.space（Yay!）の **サークル** と **タイムライン** へ、決めた文を投稿し、前に自分が投稿した分を消していく道具。
連続運転（`run.mjs`）は **2026-10-05 23:18 に起動**（5分ごと。投稿先は参加中のサークル全部とタイムライン）。止めるまで続く。

> 2026-10-07 に、`yay自動投稿/` と `discord-ch自動投稿/` と X フォロー整理ツールを **このアプリ（SNSアプリ）の1つのフォルダ** にまとめた。
> 全体の説明は `../README.md`。`config.json`（手元だけ・コミットしない）は `config.example.json` をコピーして作る。

```
bash launchd.sh install                                      # 連続運転を始める（参加中のサークル＋タイムラインへ intervalSeconds ごとに。自動起動つき）
node run.mjs --cycles 2 --targets timeline --interval 60 --cleanup   # 動作確認（有限回・最後に自分の投稿を消して終わる）
touch STOP                                                   # 止める（いまの周回が終わってから、プロセスごと終わる）
                                                             # ※ アプリの「自動投稿」タブの「投稿を止める」なら、動いたまま投稿だけ見合わせる（再開もアプリから。poster/README.md）

node trial.mjs --dry                     # 文を入れて「投稿」ボタンが押せる状態か見るだけ（送信しない）
node trial.mjs --target group:408344     # 1回投稿 → 30秒見せる → その投稿だけ消す
node trial.mjs --target timeline         # タイムラインで同じこと
```

- 専用の Chrome（`chrome-profile/`、デバッグポート 9334）を使う。ログインは、その窓で手で一度だけ。
  無ければ手で起動: `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --remote-debugging-port=9334 --user-data-dir=<このフォルダ>/chrome-profile https://yay.space/`
- 文は `config.json` の `text`
- 記録は `logs/`（`posted.jsonl` が投稿・削除の記録、`run.log` が動作の記録）。`chrome-profile/` にはログイン情報が入るのでコミットしない

## 投稿する文を画面で変える

アプリ（https://x-follow-manager-wine.vercel.app）の **「自動投稿」タブ** の **「Yay」**（ディスコードとは別の枠）で文を直して保存すると、
**次の周回（最大5分後）から**その文になる。止めたり再起動したりは要らない。Yay の文は1つだけ。

- 周回の頭で `cloud.mjs` が画面で保存した文を取り、`config.json` の `text` にも控える。届かないときは、その控えで続ける（`run.log` に1回だけ記録）
- 周回の頭と終わりに「動いている・最後の投稿・今日の件数」を報告する（画面の「Macは動いています」。20分報告が無いと「応答なし」）
- `config.json` の `"cloud": { "url", "tokenFile" }` が接続先。消すと手元の `text` だけで動く
- 合鍵はディスコードと共通で、`../discord/.hub-token`（このフォルダに同名のファイルがあればそちらが先）。
  画面のログインとは別物で、文を読む・状態を報告するだけ。Supabase には sha256 の値だけを置いている
- 文が差し替わると `run.log` に「文が差し替わりました（クラウド）」が出る
- 以前の編集画面（https://ch-post-editor.vercel.app ）へ戻すときは、`config.json` の `cloud` を `{ "url": "https://ch-post-editor.vercel.app" }` に戻して再起動する

## 起動のしかた（自動起動・launchd）

Mac にログインすると自動で始まり、Claude アプリを再起動しても止まらない（2026-10-06 に、`nohup … &` で起動したものが、Claude アプリの再起動に巻き込まれて止まった）。

```
bash launchd.sh install     # 自動起動を入れて、いま始める（~/Library/LaunchAgents/local.yay-auto-post.plist）
bash launchd.sh status      # 動いているか（state = running なら動いている）
bash launchd.sh restart     # 止めたあとの再開（STOP を消して始め直す）
bash launchd.sh uninstall   # 自動起動を外して、止める
touch STOP                  # 止める（いまの周回が終わってから止まる。作ったままなら、次のログインでも止まったまま）
```

- 動いているかは `bash launchd.sh status`。`pgrep "node run.mjs"` では見つからない（launchd 起動は node のフルパスで動くため）。`pgrep -fl run.mjs` なら見える
- 作りの注意（`launchd.sh` の冒頭にも書いてある）: launchd 自身は Desktop の中を開けないので WorkingDirectory は使わず、標準出力のログは `~/Library/Logs/local.yay-auto-post.log` に出る。
  起動プログラムは node を直接指す（sh や ls を挟むと Desktop を読めない）。KeepAlive は Crashed のみで、制限(403/429)などで道具が自分で止まったときは再起動しない
- node のバージョンを上げたら、もう一度 `bash launchd.sh install`
- **専用 Chrome のウインドウは閉じてよい。** タブやウインドウを閉じても、Chrome ごと終了しても、次の周回で道具が自分で
  つなぎ直す（Chrome が無ければ立ち上げ直す。ログインはプロフィールに残っている）。2026-10-06 に、タブを全部閉じる・Chrome を終了する、の両方を実地で確認済み
  （ただし、閉じてから次の周回までは投稿されない。最長で5分ほど空く）
- 二重起動は `logs/run.pid` で防ぐ（2つ目は「すでに動いています」で終わる）

## 連続運転のしくみ

各場所で「前の自分の投稿を消す → 新しく投稿する」を、`intervalSeconds`（既定300秒）ごとに繰り返す。
- 前の投稿を消せなかった場所には、新しく投稿しない（積み上がらないように）
- **消えたことは、投稿そのもののページで確かめる**: 投稿のページを開くとサーバーが `GET /v2/posts/<番号>` に答える（200=ある / 404=消えている）。
  「一覧に出てこない」だけでは消えた証拠にしない（一覧が読めていないだけのことがあり、2026-10-06 に2件が数時間残った）。
  一覧に出ないがまだあるときは、投稿のページのカードから消す。確認できないときは新しく投稿せず失敗扱い（3回続けると止まる）
- ログイン切れ・HTTP 403/429・投稿の拒否・3回続けての失敗では、止まって Mac の通知を出す
- 一覧に出てこない前の投稿（手で消された等）は、記録だけ閉じて先へ進む
- 二重起動は `logs/run.pid` で防ぐ
- `run.mjs` を直したときの入れ替えは、`touch STOP` → 止まるのを待つ → `rm STOP` → 再起動。止めた時点で残っていた投稿は、新しい版が最初に消してから投稿する（積み上がらない）
- **投稿先は「タイムライン ＋ 参加中のサークル全部」**（2026-10-07〜）。`config.json` の `"targets": "auto"` のとき、周回の頭ごとに
  サークル画面（`/groups`）が取っている参加中の一覧（`GET /v2/groups/mine`）を読んで決める。**新しく参加したサークルは、次の周回から自動で対象になる**
  （`run.log` に「参加中のサークルが変わりました」と出る）。番号の配列（`["timeline","group:408344"]`）を書くか `--targets` を付けると、その固定の一覧で動く
  - **入れないもの**（`targets.mjs`。コードに固定してあり、config から消しても外れる）: 名前に「ショタ」「ロリ」を含むサークル（ひらがな・全角半角も同じ扱い）と、
    既知の2つ（387028・264892）。未成年がいる可能性があり、そこへ連絡をうながす投稿を機械で繰り返し出さない、という決め。外したサークルは理由つきで `run.log` に出る
  - 入れたくないサークルを足すには、`config.json` の `excludeGroups`（番号）か `excludeNameWords`（名前に含む言葉）に書く（足せるだけで、固定の除外は減らせない）
  - 数の上限は `maxGroups`（既定20）。超えた分は対象にせず、通知とログで知らせる
  - 読み込みに失敗した周回は、前に読めた一覧（`logs/targets.json`）で続ける。参加中が突然0件になったときは読み違いとみなして前の一覧で続ける
  - 同じサークルが3周続けて失敗したら、そのサークルだけ約1時間お休みする（投稿できない設定のサークルが、ほかの場所まで巻き込んで止めないため）
  - サークルから抜けた・除外した場所に残っている自分の投稿は、自動では消さない（`posted.jsonl` に記録は残る）
  - 試す: `node --test targets.test.mjs`（選びかたの単体テスト）

## 消す投稿の決めかた（安全のため）

- 消すのは **この道具が投稿して、`posted.jsonl` に番号を残した投稿だけ**。手で投稿した分・他の人の投稿は消さない
- 削除の直前に、カードの投稿者が自分であることも確かめる
- 「削除してよろしいですか」の確認画面の「はい」が1つに絞れないときは、押さずに止まる

## 画面の作り（変わると動かなくなる所）

- 投稿欄は、クリックすると入力用の本物の欄（編集用の部品）に入れ替わる。textarea に値を入れても「投稿」ボタンは有効にならないので、
  クリックして実際にキー入力する（`yay.mjs` の `typeIntoComposer`）
- 投稿の送信は `POST /api/posts`（201）。投稿番号は、画面に出た「自分の・同じ文の・新しい」カードのリンク `/post/<番号>/` から読む
- 削除は、カードの `.Menu__handle` →「削除」→ 確認画面（`.ConfirmBox`）の「はい」。確認画面の部品は他のもの（ブロック・辞退）も隠れて並んでいる
