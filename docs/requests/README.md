# docs/requests/ — Cowork からの依頼を置く場所

Cowork（要件整理担当）がここに Markdown を1件1ファイルで書く。
書き込みは **ワークスペースの常駐**（`../../scripts/cowork-daemon.sh`）が5秒ごとに見つけて、
このアプリのフォルダで Claude Code をヘッドレス起動する。
**このREADME自体は監視対象から外してある。**

## 1ファイルの書き方

ファイル名は内容が分かるものにする（例：`一覧の並び順を変えたい.md`）。
中身はこの3点が読み取れれば着手される。決まった書式は要らない。

```markdown
# ここに何をしたいかの見出し

## 何を変えたいか
いまどうなっていて、どう変わってほしいか。

## どの画面／どのデータか
分かる範囲でいい。

## 既存データをどう扱うか
既に入っているものをどうするか（触らなくていいならその旨）。
```

スクリーンショットを置いてもいい（`screenshots/` などに入れる。画像も検知される）。

## 書かなくていいもの

文言・色・並び順・細かいUIの詰めは、書かなければこちらで妥当な案を採って進める。
決めたことは実装後の報告で「こちらで決めた」と明示される。

## 止まる場合

次に当たるものは、実装せずに `.cowork/waiting.txt` に理由を書いて止まる。

- 何をしたいのかが依頼から読み取れない
- Dexie の主キー変更など、`src/db/` のバージョンチェーンを壊しうる移行
- X API の従量課金が増える変更（取得件数を増やす・自動実行の間隔を短くする等）
- cron の秘密鍵・環境変数の変更（`cron-secret.local` / Vercel 側の設定が要るもの）
- 本番データを消す／作り直す性質の変更

## いまの状況を見る

```
bash ../scripts/cowork-watch.sh --app "Xフォロー整理ツール"
```
