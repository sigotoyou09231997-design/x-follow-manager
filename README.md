# SNSアプリ（旧: X フォロー整理ツール）

X のフォロー整理・予約投稿と、掲示板（discord-ch.site）・Yay の自動投稿を1つにまとめた個人用Webアプリ。
Mac で動く自動投稿の投稿役は `poster/` にある（`poster/README.md`）。

3つの機能を持つ。**アプリを開いて最初に出るのは「自動投稿」の1画面だけ**（2026-10-15。以前のタブ・メニューバー・＋ボタンは無くした）。

- **今月のAI料金**（`UsageMeter.tsx`）: トップのいちばん上に、今月使った金額（見積もり）・上限・割合を、棒つきで出す。8割を超えるとオレンジ、上限に達すると赤（上限に達すると新しい投稿を作らない）。数えているのは X の自動運転（文を作る・文体のまとめ・投稿）の分だけで、ディスコード・Yay は AI を使わない
- **稼働スイッチ**（1枚のカードに1行ずつ）: X の自動運転 → ディスコード → Yay。状態（Mac が動いているか・停止中・依頼中）と「止める／再開」を押せる。Mac から応答が途絶えたときだけ、いちばん上に「投稿役を再起動する」が出る
- **X のこれから投稿される予定**: **「投稿可能」（緑の枠・時刻になると投稿される）と「確認待ち」（オレンジの枠・押すまで投稿されない）の2つのエリア**に分け、投稿可能を上に（それぞれ近い順。確認待ちが無ければ確認待ちの枠は出さない）。時刻は「今日／明日／日付」＋大きな時刻＋「あと◯時間」（`src/lib/xAutopilot/whenLabel.ts`）。「取り消す」で外し、近い時刻の枠から別の文で作り直す
- **ディスコード・Yay の、いま投稿されている文**（`ChannelTextRow.tsx`）: **稼働スイッチと同じ1枚のカードの中**（ディスコード・Yay それぞれの「止める」の行の下）に出し、**過去の文はドロップダウンで選んで「この文にする」**（選んだだけでは保存しない。保存は詳細の画面と同じ版つきで、順番に回す文が複数あれば足す・いっぱいなら断る）
- **画面の右下に、丸いメニューボタンが付いてくる**（`src/components/QuickMenu.tsx`。どの画面でも表示）。押すと下からメニューが出て、自動投稿のトップ・自動投稿の文と設定・予約投稿・フォロー整理・残すリスト・履歴・設定へ、一度で移れる（いまの画面に「いまここ」）
- ほかの機能は **右上の設定 → 「機能」** から開く（自動投稿の文と設定／予約投稿／フォロー整理／残すリスト／履歴）。開いた画面は、ヘッダーの「‹ 戻る」で1つ前へ戻る（設定から開いたものは設定へ、設定はトップへ）
- ログインしていない・サーバーに接続できない環境（Artifact版など）では、トップは案内だけが出る（`src/artifact/AutoPostViewStub.tsx`）
- 組み立ては `src/components/autopost/AutoPostHome.tsx`（トップ）・`ChannelControls.tsx`（スイッチの行）・`XAutopilotPanel.tsx` の `variant="summary"`。文や回数を変える詳細（ディスコード・Yay・X のタブ）は `AutoPostView.tsx`

| 機能 | 動く場所 | 外部通信 |
| --- | --- | --- |
| 非相互フォロー整理 | ブラウザ内で完結 | なし |
| 予約投稿（AI下書き・自動投稿） | サーバー（Vercel + Supabase） | Supabase / Anthropic / X API |
| 毎日投稿（AIが毎回書く繰り返し） | サーバー（Vercel + Supabase） | Supabase / Anthropic / X API |
| アップデート通知 | ブラウザ + サーバー | Supabase / Web Push |
| 自動投稿（掲示板・Yay） | 文と状態の置き場はサーバー、投稿そのものはMac | Supabase |

非相互フォロー整理は今まで通り、アーカイブZIPをブラウザ内だけで解析します。
予約投稿は「ブラウザを閉じていても時間になったら投稿される」必要があるため、サーバー側で動きます。

## 自動投稿（掲示板・Yay）

「自動投稿」タブは、Mac で動いている投稿役（掲示板 discord-ch.site と Yay の自動投稿）が使う
**文を変える画面**と、「Macは動いています・最後の投稿・今日の件数」の表示です。
投稿そのものは Chrome を操作する必要があるため Mac で動き続け、Vercel の中では動きません。

```
画面（このアプリの「自動投稿」タブ）          Mac の投稿役
   │ Supabase のログインで本人確認              │ 合鍵（Bearer）で本人確認
   ▼                                           ▼
 api/autopost.ts ── autopost_channels ◀── api/poster-text.ts   … 投稿の直前に文を読む
                    （文・履歴・版・状態）  ◀── api/poster-status.ts … 数分おきに「動いています」を報告
```

- 保存先は Supabase の `autopost_channels`（文・履歴・状態）と `autopost_poster_keys`（Mac の合鍵の sha256）。
  作るのは `supabase/sql/005_autopost.sql`。**これを実行するまで、タブは「保存先がまだ用意されていません」と出す**（他の機能には影響しない）
- 文は保存のたびに版が進む。別の端末で先に保存されていたら、上書きせず知らせる（画面の書きかけは残る）
- 外れた古い文は「これまでの文」に残り、押すと書きかけに戻せる
- `api/poster-text.ts` / `api/poster-status.ts` は、以前の編集画面（ch-post-editor）と同じ URL・同じ返し方。
  Mac 側は `config.json` の `cloud.url` と合鍵を差し替えるだけでつなぎ替えられる
  （2026-10-07 に、ディスコード・Yay とも新しい受け口へ切り替え済み）
- **`api/` 直下の `.ts` は、テストも含めて全部「関数」として数えられ、Vercel の上限は12個**（超えるとデプロイが失敗する。エラー文は出ない）。
  新しい関数を足す前に `ls api/*.ts | grep -v '^api/_' | wc -l` を見る。テストは `api/_lib/` に置く
- 合鍵でできるのは「文を読む」「状態を報告する」「再起動の依頼を受け取って結果を書き戻す」だけ。文の書き換えはできない
- **止まったときの通知と、スマホからの再起動**（2026-10-12）
  - 毎分の `publishDue` の末尾が `api/_lib/posterWatch.ts` を呼び、投稿役の報告が20分途絶えたら（画面で止めている間・3日より古い報告は除く）、
    通知を有効にした端末へ Web Push を1回送る。タップすると `/?open=autopost`（自動投稿タブ）が開く
  - 画面の「投稿役を再起動する」→ `api/autopost.ts`（POST `{ restart: true }`）が `autopost_restart` に依頼を置く
    （作るのは `supabase/sql/008_autopost_restart.sql`。**実行するまで、再起動のカードは「準備中」と出る**。他の機能には影響しない）
  - Mac の `poster/remote/`（1分ごとに起動）が `api/poster-command.ts` で依頼を見つけ、**止まっている投稿役だけ**を入れ替えて結果を書き戻す。
    動いているもの・STOP があるものには触らない。Mac 本体は再起動しない（FileVault が有効で、再起動すると Mac の前でパスワードを打つまで全部止まるため）


# 予約投稿のセットアップ

初回だけ、以下の4つを順に設定します。

## 1. X（Twitter）側

X API は 2026年2月から**従量課金制**になり、無料枠はありません。

| 項目 | 料金 |
| --- | --- |
| 投稿1件 | $0.015 |
| **URLを含む投稿1件** | **$0.200** |
| 画像のメタデータ（代替テキスト） | $0.005 |

1. https://console.x.com で開発者登録し、appを作る
2. 開発者コンソール（https://console.x.com）でクレジットを購入する（残高が尽きると投稿が失敗する）
   - **自動リチャージ**（金額としきい値）と **Spend cap**（1請求サイクルの上限）を必ず自分で設定する
3. app の **User authentication settings** を開き、以下を設定する
   - App permissions: **Read and write**
   - Type of App: **Web App**（＝confidential client。client secretが発行される。
     Native App / Single Page App を選ぶとsecretが出ず、この実装は動かない）
   - Callback URI: `https://<あなたのVercelドメイン>/x-callback`
     - **完全一致**で判定される（プロトコル・末尾スラッシュ含む）。1つのappに最大10個まで登録できる
     - ローカル検証用には `http://127.0.0.1:3000/x-callback`（`vercel dev`）を追加する。
       **`localhost` は不可**で、Xが許可するのは `http://127.0.0.1` だけ。
       ブラウザも `localhost` ではなく `127.0.0.1` で開くこと（origin が一致しないと弾かれる）
   - Website URL: 任意
4. **Client ID** と **Client Secret** を控える

> スコープは `tweet.read tweet.write users.read media.write offline.access` を使います。
> `offline.access` がないとリフレッシュトークンが発行されず、2時間で投稿できなくなります。

## 2. Supabase 側

LIFE HUB（todoアプリ）と同じプロジェクトに相乗りできます。

1. SQL Editor で `supabase/sql/001_x_scheduler.sql` を実行する
   - `x_accounts`（Xのトークン置き場）、`scheduled_posts`（予約）、Storageバケット `x-post-media` が作られる
   - `x_accounts` は **RLSを有効にしてポリシーを1つも作らない**設計です。ブラウザからは1行も読めず、
     service_roleキーを持つサーバー関数だけが触れます（トークンが漏れると本人になりすまして投稿されるため）
2. Authentication → Providers で **Google** を有効にする
3. Authentication → URL Configuration の Redirect URLs に以下を追加する
   - `https://<あなたのVercelドメイン>/**`
   - `http://127.0.0.1:3000/**`
   - `http://localhost:5173/**`
4. Project Settings → API から **Project URL**、**anon key**、**service_role key** を控える

## 3. Vercel 側

1. このディレクトリをVercelにデプロイする
2. 環境変数を設定する（`.env.example` を参照）

   | 変数名 | 値 | 備考 |
   | --- | --- | --- |
   | `SUPABASE_URL` | SupabaseのProject URL | ブラウザへは `/api/config` 経由で配られる |
   | `SUPABASE_ANON_KEY` | Supabaseのanon key | 同上（`VITE_SUPABASE_ANON_KEY` でも可） |
   | `SUPABASE_SERVICE_ROLE_KEY` | Supabaseのservice_role key | **サーバー専用。ブラウザには絶対に出さない** |
   | `ANTHROPIC_API_KEY` | AnthropicのAPIキー | サーバー専用 |
   | `X_CLIENT_ID` | XアプリのClient ID | サーバー専用 |
   | `X_CLIENT_SECRET` | XアプリのClient Secret | サーバー専用 |
   | `CRON_SECRET` | 自分で決めるランダムな長い文字列 | サーバー専用 |
   | `VAPID_PUBLIC_KEY` | Web Pushの公開鍵 | ブラウザへは `/api/config` 経由で配られる |
   | `VAPID_PRIVATE_KEY` | Web Pushの秘密鍵 | **サーバー専用。ブラウザには絶対に出さない** |
   | `VAPID_SUBJECT` | `mailto:自分のメールアドレス` | サーバー専用 |

   > `VAPID_*` はアップデート通知を使う場合だけ必要です（後述の「アップデート通知」）。
   > 未設定でも他の機能は動き、通知の項目が設定画面に出なくなるだけです。

   > **接続情報はビルド時ではなく実行時に配ります。**
   > Vercelでは「Sensitive」に設定した変数がビルド時に渡されず、さらにビルドキャッシュの
   > 影響も受けるため、`VITE_` 方式だと「環境変数は正しいのに画面には未設定と出る」という
   > 切り分け不能な状態に陥ります（実際に踏みました）。
   > そのため `api/config.ts` が実行時に `SUPABASE_URL` / `SUPABASE_ANON_KEY` を返し、
   > ブラウザは起動時にそれを取得します。これにより、**環境変数の設定漏れがあっても
   > 画面のコードが最適化で消えることがなくなり**、原因を切り分けられるようになります。
   > （Vercelの仕様上、環境変数の値を変えた後は再デプロイが必要です。ただし値が空でも
   > ビルド結果は変わらないので、再デプロイすれば必ず反映されます。）
   > ここで配るのは公開前提の2つだけで、service_role key や各種シークレットは返しません。
   >
   > 設定漏れの切り分けは `https://<ドメイン>/api/config` を開けば分かります
   > （どれが設定済みかを true/false で返します。値は返しません）。

3. 環境変数はすべて Sensitive にして構いません（実行時にしか使わないため）
4. **保存後、値がちゃんと入っているか `https://<ドメイン>/api/config` で確認する**
   （キーだけ登録されて値が空、という状態になっていても画面上は見分けがつかないため）

> **`api/` 配下の相対importには必ず `.js` 拡張子を付けること。**
> `package.json` が `type: module` なので、Vercel上ではNodeのESM規則が適用され、
> 拡張子なしの相対import（`from './_lib/auth'`）は `FUNCTION_INVOCATION_FAILED` になります。
> npmパッケージは解決できるのに自分のファイルだけ読めない、という紛らわしい症状が出ます。

## 4. 定期実行（毎分のチェック）

**Vercel Cron は使いません。** Hobbyプランは cron が1日1回までで、しかも実行時刻が±1時間ずれるため、
予約投稿には使えません。代わりに Supabase の `pg_cron` から毎分 `/api/publishDue` を呼びます。

1. `supabase/sql/002_publish_cron.sql` の `<>` 部分を自分の値に置き換える
2. SQL Editor で実行する
3. 動作確認

   ```sql
   select * from cron.job;
   select * from cron.job_run_details order by start_time desc limit 20;
   select id, status_code, error_msg, created from net._http_response order by created desc limit 20;
   ```

> Supabase無料プランは1週間アクセスがないとプロジェクトが一時停止します。
> このcronが毎分動いていれば停止しませんが、**一度停止するとcron自身では復帰できません**。

# 毎日投稿する

「繰り返し投稿」は、そのままだと**毎回まったく同じ文面**を投稿します。週1の告知ならそれでいいのですが、
毎日出したい場合は同じ投稿が並ぶだけになります。そのための設定が **AIおまかせ** です。

投稿を作る画面で

1. 「繰り返し投稿にする」→ 毎日・投稿する時刻を選ぶ
2. 「毎回ちがう本文をAIに書いてもらう」を入れる
3. 「何について書くか」にお題を書く（文体の希望も一緒に書いてよい）

これで本文欄は消えます。書いても使われないためです。

お題の欄には**ひな形のボタン**（毎朝のあいさつ / 今日やること / ひとこと日記）が
出るので、毎朝おはようを言うだけなら「毎朝のあいさつ」を押すだけで済みます。
押すと欄が埋まるので、そこから自分の言葉に直せます。

> お題には「**毎回入れること**」と「**毎回変えること**」の両方を書くのがコツです。
> 「毎朝のあいさつ」とだけ書くと、AIは前日と同じ書き出しを避けようとして
> 肝心の「おはよう」を外しにいきます。ひな形はどれもこの2つが書いてあります。
> （プロンプト側でも、あいさつや名乗りは毎回入れてよいと明示しています）

| | 動き |
| --- | --- |
| いつ本文が作られるか | 前回の投稿が出た直後（毎日なら約1日前） |
| 誰が作るか | `api/publishDue.ts` が Anthropic を呼ぶ |
| 同じ話にならないか | この繰り返しで投稿済みの直近10件をAIへ渡し、避けさせている |
| 気に入らないときは | 投稿までのあいだ一覧に本文が並ぶので、そこで編集する |
| 作れなかったときは | その回は作らず、15分おきにやり直す。理由は繰り返しの札に赤字で出る |

作れなかったときに前回と同じ文面を代わりに出す、ということはしません。
それをやると「AIが書いていると思っているのに毎日同じ文章が出ている」という、
いちばん気づけない壊れ方をするためです。

> **費用は投稿1回につきAI呼び出し1回**です（`ANTHROPIC_API_KEY` の残高から引かれます）。
> 1回の `publishDue` で生成するのは最大2件までにしてあります。毎分呼ばれるので、
> 繰り返しをいくつ登録しても数分で行き渡り、投稿そのものが生成待ちで遅れることはありません。
>
> やり直しを15分おきに絞っているのは、お題そのものが原因で失敗し続ける場合
> （AIが書くのを断る題材など）に、毎分呼び直して課金だけが積み上がるのを防ぐためです。
> 「何回か失敗したら諦める」にしていないのは、AI側の一時的な不調で止まったまま
> 二度と投稿されなくなる方が困るからです。

> 画像は付きません。AIおまかせのときは本文欄ごと隠しているため、添付する場所がありません。
> 画像を毎回付けたい場合は、AIおまかせを使わない繰り返しにしてください。

# X の自動運転（過去の投稿から文体を学んで、AIが前もって予約に並べる）

「自動投稿」タブの **X** で使います。お題を人が決めなくても、**自分の過去の投稿を読んで文体と話題をAIがまとめ**、
その文体で新しい投稿を**前もって予約に並べます**。並んだ予約は、ふつうの予約と同じく「予約投稿」タブで
見て・直して・消せて、何もしなければ時刻に投稿されます（人が見ずに出る形ではありません）。

## セットアップ

1. 「予約投稿」タブで **Xと連携**する（上の「予約投稿のセットアップ」が済んでいること）
2. Supabase の SQL Editor で `supabase/sql/007_x_autopilot.sql` を実行する（設定・履歴の表と、同じ枠を二重に作らない索引）
3. X API にクレジット（従量課金）が入っていること。**自分の投稿を読む**ので、アプリの権限に `tweet.read` が必要（連携の権限に入っている）

SQL を流す前でも、他の機能は今までどおり動きます。X のタブだけが「保存先がまだ用意されていません」になります。

## 使い方

| 手順 | 何が起きるか |
| --- | --- |
| 過去の投稿を読んで、文体をまとめる | X から自分の投稿（返信とリポストを除く最大200件）を読み、AIが「この人らしさ」（語調・語尾・長さ・よく書く話題）をまとめる。まとめの中身は**画面には出さない**（画面は「まとめ済み」とだけ表示）。見たいときは Supabase の Table Editor で `x_autopilot` の `profile` 列を開く。反応の多い投稿を足すときも、お手本を選ぶときも、**いちばん新しい投稿から半年の範囲**の中から選ぶ（昔の型の投稿が、反応が多いぶん混ざって、いまは使っていない書き方で投稿されるのを防ぐ。`recentWindow`）。すでに作ったまとめは、画面の「文体をまとめ直す」を押すまで古いまま |
| 試しに1本書く | いまの文体で1本だけ書かせる。予約には入れない。気に入らなければ設定を変えて、もう一度 |
| 自動運転を始める | 時間帯の中に、1日の投稿数ぶんの枠を、日ごとに少しずつずらして作る。数日先までの枠に、AIが書いた投稿を予約として並べる。毎分の実行（`publishDue`）が、足りない枠を補う |
| 止める | まだ出ていない自動運転の予約を取り消す。止めたあとに出てしまうことはない |

- 並んだ予約は、一覧の **取り消す** で外せる。**外した枠は空きとして、いちばん近い時刻の枠から、別の文で作り直す**（画面の「取り消す」の直後に、その場で1つ（数十秒）。残りの空きは毎分の補充）。以前は「取り消した枠は作り直さない」で、今日・明日の枠を取り消すと、自動運転を止めて始め直すまで戻らなかった。作り直した予約が生きていれば、その枠はもう空きではない（繰り返さない）。作り直しが失敗しても、毎分の補充がやり直す
- **取り消した文は、削除せず「取り消した」印（`scheduled_posts.error_message`）を付けて残し、次に書くときの「出さないもの」としてAIに見せる**（直近10件。似すぎの検査にも使う）。取り消しても似た話題・同じ型の文が出続けるのを防ぐため。印が付くのは画面の「取り消す」だけ。**「止める」での一括の取り消しと、予約投稿タブでの削除の枠は、いままでどおり作り直さない**（本人が嫌がったわけではない・消すと決めた枠のため）。取り消したものは予約投稿の一覧にも出さない
- **文を作るたびに、本人の最新の投稿を取り入れる**（2026-10-15）。①履歴が2時間より古ければ、作る前に X から読み直す（差分だけ・新しい投稿が無ければ費用は出ない・読めなくても、あるもので書く）。②直近の本人の投稿から、長さ・句点・絵文字・「w」「草」などの割合を**毎回計算**して AI に渡す（AI は呼ばないので無料。`src/lib/xAutopilot/recentStyle.ts` の `describeRecentStyle`）。書き方は変わる（2026年にそれまでの型が消えた）ので、`voiceGuide.ts` の文字だけに頼らない。AI 下書きと繰り返しの AI おまかせは X の履歴を持たないので、`voiceGuide.ts` だけ
- **自動運転が投稿した分は、学習（お手本・傾向・文体のまとめ）に使わない**。`scheduled_posts.posted_tweet_ids` で見分けて、履歴から外す。外さないと、自動運転が出した文が履歴に戻って次のお手本になり、AI が好む話題が自分で自分を強める（実例: ハイボールなどお酒の話に偏った）
- **毎回同じ骨組み（「◯◯、△△。□□。」の短い不満＋オチ）にならないよう、枠ごとに「型」と「長さ」を指定する**（2026-10-15、本人「また似たような文章しか出ない」）。`src/lib/xAutopilot/variety.ts` が、15種類の型（一言の言い切り・問いかけ・二つを比べて迷う・実況・自分へのツッコミ・願望・呼びかけ・素朴な疑問・前置き＋切り返し・並べて一言・気づき・話しかけ・否定から入る・短い3行・決めつけ）と、3種類の長さ（短め15〜30字・ふつう30〜60字・長め60〜110字）から、枠ごとに決める。さらに、最近の投稿で2回以上使っている書き出し、3回以上使っている締めは避けさせる。**長さが範囲の外の案、最近の2本以上と同じ書き出しの案は使わず、理由を伝えて書き直させる**（書き直しは2回まで）。事実や体験談を作らない決まりは、そのまま
- **同じ言葉・同じ題材の繰り返しを避け、まだ書いたことがない題材を出させる**（2026-10-15、本人「焼き芋やハイボールが多い。今まで書いたことがない内容で、自分の言い回しで」）。自動運転が最近出した投稿（60件まで）の**2本以上に出ている言葉**を「使いすぎの言葉」としてAIに渡し（`src/lib/xAutopilot/words.ts`）、**案にその言葉が入っていたら使わず、理由を伝えて書き直させる**。本人が自分で書く言葉（会社・ゲームなど）は数えない。さらに、**過去の投稿（本人・自動運転）に1度も出ていない題材の候補**（体験談にならない、見たこと・思ったこと・あるあるの30題材から、枠ごとに違う4つ）を渡し、そこから選ばせる。語尾・口調・文の長さなど、言い回しは、文体のまとめとお手本から取り入れる。事実や体験談を作らない決まりは、そのまま
- **取り消した文を全部残して分析し、次から取り入れる**（2026-10-15、本人「かなりの数を取り消している。どんな単語や文章が取り消されているか分析して取り入れて」）。取り消した文は、これまでも削除せず `scheduled_posts` に「取り消した」印つきで残している。毎回の文作りで、**取り消した文を新しい300件まで読み**（`api/_lib/autopilotEngine.ts` の `REJECTED_FOR_ANALYSIS`）、`src/lib/xAutopilot/rejectedAnalysis.ts` で数える: ①取り消した文のうち2本以上に出ていて、残した文には少ない**言葉**、②**話題の括り**（お酒・晩酌など）。これを「本人がよく取り消す言葉・話題」としてAIに渡し、**取り消しが3回以上で割合の高い言葉は、案に入っていたら使わず書き直させる**。文そのものをAIに見せるのは、新しい10件のまま。**画面（自動投稿の文と設定 → X）の「取り消した文の分析」**で、言葉・話題を回数つきで見られる（使わない言葉は濃い色）
- **話題の偏りを毎回数えて避けさせる**。話題を大きな括り（お酒・食べ物・会社・ゲーム…）で数え、自動運転が最近出した12件のうち3件以上／本人の最近20件のうち5件以上（30%）の括りを「最近多すぎる話題」として、ふだん書くのに最近出ていない括りを「最近少ない話題」として AI に渡す（括りの定義は `TOPICS`。本人の履歴に根拠が無い括りは勧めない＝無かった体験を作らせない）。ガイドにも「お酒の話は10本に1本まで」
- **投稿する前に、自分で確認して「投稿可能」を押す**（2026-10-15、既定はオン。設定 `requireApproval`）。オンのあいだ、AIが並べる投稿は**確認待ち**（`scheduled_posts.status = 'draft'`。毎分の投稿は `scheduled` しか拾わないので、時刻が来ても投稿されない）。各予約の「投稿可能にする」を押すと `scheduled` になり、時刻になると投稿される（時刻を過ぎていれば1分以内）。**投稿可能な予約の中で、これよりも前の時刻の投稿可能な予約が無ければ、投稿時刻を「いまから5分後」に前倒しする**（`src/lib/xAutopilot/approve.ts`。待たせず、押し間違いに気づく猶予だけ残す。確認待ちは順番を塞がない。前に投稿可能な予約があれば時刻はそのまま）。**今日の投稿数（出した・出している・投稿可能）が、設定の「1日の投稿数」に達している日には、前倒しも投稿可能にしたときの移動もしない**（上限に達していれば、次の日の枠へ移る）。トップの稼働スイッチの行に「今日の投稿 2/3本」と出る。**前に投稿可能な予約があるときは、その列のすぐ後ろ（最後の投稿可能な予約から30分以上あけた、次に空いている枠）へ詰める**（遠い日の予約を投稿可能にしても、明日の午前など、次に空いている枠へ移る）。**前倒し先は、「いまから5分後」と「直前の自動運転の投稿から30分後」の遅いほう**（連投に見えないため）。**時刻を動かすのは、本人が「投稿可能にする」を押した、その1回だけ。押していない予約を、あとから自動で動かしたり早めたりはしない**（2026-10-15、「勝手にツイートされた」を受けて、毎分の前詰めはやめた）。押す前に、ボタンの中に「押すと、今日 13:48 に投稿されます」と、投稿される時刻を出す（同じ計算）。**「編集」で本人が投稿時刻を変えた予約には、`segments[0].fixedTime` の印を付け、投稿可能にしたときの前倒しも、毎分の前詰めも、しない**（本人が選んだ時刻に出す）。本文だけ直したときは付かない。「確認待ちに戻す」で `draft` に戻せる。**投稿可能にしたあと、その予約より前の時刻にまだ作っていない枠があれば、いちばん近い枠から別の文を作る**（「取り消す」のあとの作り直し `refill` と同じ。空きが無ければ何も作らない）。**確認待ちは1件ずつ作る**（2026-10-25、本人の指示「AIの生成文章は一個ずつが良い。予算的にもそっち」。確認待ちが残っているあいだはAIを呼ばず、投稿可能にする・取り消すと次の1件を作る。`MAX_PENDING_DRAFTS`、`api/_lib/autopilotEngine.ts`。以前は最低4日先まで作り置いていた）。確認待ちも枠は埋まっている扱い（同じ枠に重ねて作らない）、「止める」では確認待ちも取り消す。****確認してから投稿する設定では、朝（6時）になってからは、今日の午前中（正午まで）の枠を新しく作らない**（`src/lib/xAutopilot/morning.ts`。本人の指示。前の日までに作ってあった午前の予約は残す）。**朝になってから作られた、今日の午前中の確認待ちは、毎分の `publishDue` が取り消す**（作られた時刻で見分ける。取り消しの印は付けない）。確認してから投稿する設定のときは、本人が「取り消す」で外した枠のうち、近い枠（いまから2時間以内・過ぎた枠）は作り直さず空けたままにし、遠い枠（たとえば明日）は作り直す**（消したのにまた同じ時間帯に出てくるのを避けつつ、候補が減る一方にならないようにする。毎分の補充も同じ決まり。`REFILL_MIN_LEAD_MS`）。確認なしの設定では、これまでどおり、取り消した枠を近い時刻から作り直す。投稿時刻から6時間たっても確認待ちのままの予約は、`publishDue` が取り消す（印は付けない）。オフにして保存すると、確認待ちだった予約はすべて投稿可能になり、以後は確認なしで投稿される。同じ枠を同時に2つ作らない最後の砦の索引に確認待ちも含める `supabase/sql/009_autopilot_draft_slot.sql` は任意（流さなくても動く。流すかは本人の了解を取る）
- **次の自動運転の投稿が出たとき、前に自動運転が出した投稿を X から消す**（2026-10-15、本人の指示。**X で消すと元に戻せない**ので、**既定はオフ**。自動運転の設定の「次の投稿が出たら、前の自動運転の投稿を X から消す」で、保存してオンにする）。オンにした時刻（`deletePreviousFrom`。サーバーが付け、画面からは送らせない）以降に出た投稿だけが対象で、**オンにする前に溜まっていた投稿には触れない**。`publishDue` が自動運転の予約（`ai_prompt` が `autopilot:`）を出した直後に、同じ人の「自動運転が出した・まだ消していない投稿」を `DELETE /2/tweets/:id` で消す（`api/_lib/autopilotCleanup.ts`）。本人が自分で書いたツイートや、ふつうの予約投稿は消さない。消した予約の行は `status: posted` のまま `error_message` に `Xから削除済み` の印を付けて残す（`posted_tweet_ids` を学習の除外に使い続けるため）。消せなかった分は印を付けず、次の投稿のときにやり直す。1回に10件まで
- 設定の「投稿数・時間帯・日数」を変えて保存すると、まだ出ていない予約は新しい設定で作り直され、最初の1本はその場で作られる（残りは毎分の補充）
- 設定を変えて「保存」を押さないまま「始める」「試し書き」などを押しても、先に保存してから動く（保存済みの古い設定では動かない）
- 設定が成り立たない（終わりが始めより前・1時間未満、時間帯に入りきらない回数、範囲外の日数・上限）ときは、黙って別の値に直さず、理由を出して保存・開始を止める。サーバーも同じ検査をして 400 で断る
- 時刻は日本時間。枠は「時間帯を回数で等分した真ん中」を基準に、日付と番号から決まるずれ（±30%）を加えるので、毎日同じ時刻にはならない
- **1日2回だけは午前に1回・午後に1回**（午前＝始め〜12:00、午後＝12:00〜18:00。時間帯の終わりが18時より早ければそこまで。午前や午後に30分以上の幅が取れない時間帯は等分に戻す）
- **今日のぶんも入れる**: 時刻が過ぎた今日の枠は捨てず、今日の残りの時間帯（今から15分後〜次の未来の枠の30分前、無ければ時間帯の終わり）に入れ直す。残りに入りきらない分は作らない（翌日へずらさない）。今日すでに投稿した・予約中の枠は作り直さない（`activeSlotKeys` で生きている枠を調べ、AIに書かせる前に除く）
- 履歴の更新は **新しい投稿だけ** を読む（読み取りは件数で課金されるので差分が安い）

## 安全のために入れていること

- 書いた文は、予約に入れる前に**検査**する: 全角140字以内・URLなし・最近の投稿と似すぎていない・
  未成年を連想させる言葉を含まない・天気や気温の言葉を含まない。通らなければ理由を伝えて2回まで書き直させ、それでも通らなければ予約に入れず、理由を画面に出す
- **天気・気温の話は書かせない**（2026-10-15、本人「天気とか不確定な情報は記事に出さないでほしい」）。自動運転は数日先の投稿を作り置きするので、出る日の天気は分からず、外れた天気の話は本人が嘘をついたことになるため。`src/lib/xAutopilot/text.ts` の `uncertainIn`（天気・気温・雨・晴れ・台風・花粉など。言葉の一致で粗いが、書き直させる費用より通してしまう費用のほうが大きいので広めに拾う。季節の名前は対象外）で検査し、文章の共通ルール（`WRITING_RULES`）にも「天気のほか、ニュース・店の混雑や営業など確かめられないことは書かない」を入れた。題材の候補から天気に頼るもの（天気予報・雨の日・洗濯物・月や星・エアコンの温度など）を外し、「最近少ない話題」に「天気・季節」を勧めない。**すでに並んでいる確認待ち・予約の文は書き直されない**（本人が取り消せば、取り消した文として次から避ける）
- 履歴にも、未成年を連想させる言葉を含む投稿は**文体を学ぶ対象に入れない**（本人の過去の投稿に含まれていても）
- AIには「作り話をしない」「過去の投稿の範囲を超えて過激にしない」「URL・ハッシュタグ・メンションを入れない」を指示している
- 同じ枠の予約は、保存先の索引で二重に作れない（画面の「始める」と毎分の補充が同時に走っても）

| 画面上部の更新バナー | アプリを開いている間 | なし（デプロイすれば動く） |
| 端末への通知（Web Push） | アプリを閉じていても | 下記の1〜3 |

**更新バナー**は設定不要です。ブラウザは1分おきとタブに戻ったタイミングで新しいビルドを
確認し、見つけると画面上部に「アップデートが来ています」と出して最新版へ切り替えます。
これまで必要だった強制リロードは要りません。
ただし**予約投稿の本文を書きかけのあいだは切り替えを待ちます**（最大5分）。
書いた文章は保存前だと画面の中にしか無く、読み込み直すと消えてしまうためです。

以下は、アプリを閉じていても通知を受け取りたい場合の設定です。

## 1. VAPIDの鍵を作る

Web Pushでは「誰が送ったか」を鍵で示します。1度だけ作って、Vercelの環境変数に入れます。

```bash
npx web-push generate-vapid-keys
```

出てきた Public Key / Private Key を、それぞれ `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` に
設定します。あわせて `VAPID_SUBJECT` に `mailto:自分のメールアドレス` を入れます
（送信先のサーバーが送信元に連絡するための決まりです）。

> **秘密鍵は他の秘密情報と同じ扱いです。** 漏れると第三者があなたのアプリの名前で
> 通知を送れるようになります。GitHubには置かず、Vercelの環境変数にだけ入れてください。

## 2. Supabase のテーブルを作る

SQL Editor で `supabase/sql/003_push_notifications.sql` を実行します。
`push_subscriptions`（通知を受け取る端末）と `app_version_state`（最後に見たデプロイ）が
作られます。後者は `x_accounts` と同じく **RLSを有効にしてポリシーを作らない**設計で、
サーバー関数からしか触れません。

## 3. 定期チェックを登録する

`supabase/sql/004_app_update_cron.sql` の `<>` を置き換えて実行します。2分おきに
`/api/checkAppUpdate` が呼ばれ、本番サイトの `/version.json`（デプロイごとに値が変わる）が
前回と違っていれば、登録済みの端末へ通知を送ります。

設定が済んだら、アプリの **設定 → アップデートの通知** で「この端末で通知を受け取る」を
押してください。端末ごと・ブラウザごとに1回必要です。

### 注意点

- **通知にはログインが必要です**（購読情報を本人の行として保存するため）。
  予約投稿タブでGoogleログインしていれば、そのまま使えます
- **iPhoneでは、ホーム画面に追加したアプリとして開いた場合のみ**通知を受け取れます。
  Safariのタブで開いている状態では、iOSの仕様上どのサイトも通知を出せません
- **この機能を入れて最初のデプロイでは通知は来ません。** 「前回見たバージョン」が
  まだ無い状態で通知すると、更新していないのに通知が飛ぶためです。
  最初の1回は基準の記録だけを行い、その次のデプロイから通知されます
- 通知が要らなくなったら、同じ画面から「この端末への通知を止める」で解除できます

## 使い方

1. アプリを開いて **右上の設定 → 予約投稿** → Googleでログイン
2. 「Xと連携する」でXアカウントを接続
3. 「投稿を作る」で書く
   - 自分で書く。スレッド（連投）、画像添付（1投稿4枚まで）、繰り返し予約に対応
   - 同じ画面の **「AIに書いてもらう」** を開くと、**「AIに伝えたいこと」** の欄が1つだけ出ます。
     思いついた順のメモや箇条書き、「淡々と、絵文字なし」のような文体の希望も、まとめてこの欄に書けば、
     Claude がそれを元に投稿できる文章を複数案作ります（書いていないことを勝手に足さない指示を入れてあります）。
     「本文に使う」でそのまま本文欄に入るので、手直しして日時を付けて予約できます。
     本文を書いてある状態で開くと、その本文もAIへ渡るので「これをもっと短く」といった書き方が効きます
   - 案をまとめて貯めておきたいときは「選んだ◯件を下書きに貯める」で下書き保存し、あとから日時を付けます
4. 一覧で「予約中 / 今日の予定 / 次の投稿 / 下書き / 繰り返し / 失敗」を確認
   （投稿済みは一覧に出さない。上部の集計の「投稿済み」の件数には数える。データは消えない）

### 仕組みの要点

- 予約は毎分チェックされ、時刻を過ぎたものから投稿されます
- **繰り返し予約**はテンプレートとして保存され、次の1回分だけが予約として作られます。
  投稿されるたびに次回分が自動で追加されるので、予約が無限に積み上がりません
- **スレッド**は2件目以降を直前の投稿への返信として繋げます。
  途中で失敗した場合、投稿済みの分は取り消せないため、何件目で失敗したかがエラーに残ります
- 一時的なエラー（レート制限・X側の障害）は最大3回まで自動リトライします。
  本文の問題（文字数超過など）はリトライせず「失敗」になります
- Xのリフレッシュトークンは使い捨てで、更新のたびに新しいものに置き換わります

### 制限

- 文字数はXの数え方（日本語1文字=2、英数字=1、URL=23固定）で280までです
- 画像はXの仕様で1投稿4枚まで
- Claude Artifact版では予約投稿は使えません（サーバーが必要なため）
